# Word 企业产品手册 Master Template 规范

## 1. 定位

本母版用于 **在途商旅企业产品手册 + 技术标/商务标产品能力章节**。不是 PPT 转 Word，也不是宣传册。核心目标是：

- A4 竖版、可打印、可导出 PDF
- Word 原生可编辑
- PC / 手机截图是功能证据，而非装饰
- 100+ 页持续使用时保持稳定的视觉系统
- 同一份产品内容可以切换不同视觉风格与空间编排

## 2. 五套真正不同的版式系统

五套样式不只是颜色主题。它们共享内容数据，但 **页面的信息阅读顺序、截图占比、能力信息组织、表格位置、价值区结构和视觉节奏均不同**。

| 样式 | 阅读逻辑 | 主版式 | 适用场景 |
|---|---|---|---|
| A｜专业蓝白·证据型 | 先看产品，再查功能 | 大截图 → 功能表 → 价值 | 通用产品功能、技术标 |
| B｜青绿·双栏型 | 一眼建立“界面-能力”对应 | 左截图 65% + 右能力 35% | SaaS、系统集成、移动协同 |
| C｜靛蓝·报告型 | 先读能力，再看界面证据 | 三能力卡 → 截图 → 补充功能表 | BI、风控、数据分析 |
| D｜金棕·杂志型 | 图文并读、编号导览 | 左大图 + 右编号说明 → 价值 | 服务、运营、实施、客户成功 |
| E｜治理绿白·卡片型 | 先建立能力矩阵，再验证界面 | 三列能力卡 → 截图 → 管理价值 | 合规、预算、风控、治理 |

### A｜专业蓝白·证据型

**空间结构：**

`标题 / 概述`
`↓`
`大尺寸 PC 截图（页面视觉主体）`
`↓`
`功能说明表`
`↓`
`应用价值横向条`

这是最标准的“投标证据页”。截图占视觉主体，表格负责让评审快速检索功能点。

### B｜青绿·双栏型

**空间结构：**

`标题 / 概述`
`↓`
`┌──────────────┬──────────┐`
`│ PC 产品截图    │ 核心能力   │`
`│ 约 65% 页面宽度 │ 约 35%      │`
`└──────────────┴──────────┘`
`↓`
`应用价值`

右侧不是重复功能表，而是将 5 个关键能力压缩为“名称 + 一句话解释”，形成截图与能力之间的视觉对应。

### C｜靛蓝·报告型

**空间结构：**

`标题 / 概述`
`↓`
`┌──────┬──────┬──────┐`
`│能力01 │能力02 │能力03 │`
`└──────┴──────┴──────┘`
`↓`
`产品界面证据（大图）`
`↓`
`剩余功能说明表`
`↓`
`管理价值`

该版式刻意改变阅读顺序，让页面更接近企业咨询报告/技术白皮书。

### D｜金棕·杂志型

**空间结构：**

`标题 / 概述`
`↓`
`┌────────────────┬──────────┐`
`│                 │ 01 能力   │`
`│   大尺寸截图     │ 说明文字  │`
`│                 │ 02 能力   │`
`└────────────────┴──────────┘`
`↓`
`01 应用价值`

右侧使用连续编号形成导览感，减少传统“标题 + 表格”的机械感，适合服务与实施内容。

### E｜治理绿白·卡片型

**空间结构：**

`标题 / 概述`
`↓`
`┌─────┬─────┬─────┐`
`│能力1 │能力2 │能力3 │`
`├─────┼─────┼─────┤`
`│能力4 │能力5 │能力6 │`
`└─────┴─────┴─────┘`
`↓`
`界面证据`
`↓`
`管理价值`

适合合规、风控、预算控制等“管理能力先于界面操作”的内容。

## 3. 页面组件体系

除标准功能页外，母版统一支持：

- `standard`：标准产品功能页，按所选 Master Style 自动采用不同空间布局
- `mobile_gallery`：1–3 个手机截图，统一高度与标签
- `pc_mobile`：管理端 + 员工端协同展示
- `process` / `steps`：业务流程、申请、审批、预订、退改、对账、结算、报销
- `dashboard`：BI / 数据看板 / 核心指标
- `overview`：能力总览、章节开篇、模块导航

## 4. 商旅 SaaS 截图规范

### PC 截图

- 建议最大宽度 148–158 mm
- 保持原始比例，不拉伸变形
- 多区域说明使用 ①②③ 编号
- 编号与功能说明一一对应

### 手机截图

- 单图居中或与说明区组合
- 2 图等宽
- 3 图等宽三列
- 高度统一，不按原始像素直接排列

### PC + 手机组合

不要简单把两个截图并排。页面必须表达：

`管理端动作 → 企业管理结果`
`员工端操作 → 移动服务结果`

## 5. 投标文件专用排版原则

1. **证据优先**：截图、流程、指标、接口关系优先于装饰。
2. **评审友好**：评审可以快速定位“功能是什么、在哪里、怎么实现、带来什么价值”。
3. **一页一主题**：不为了节省页数把不相关功能挤在同一页。
4. **文字可编辑**：核心文字必须可搜索、可复制、可编辑。
5. **不做 PPT 化**：避免大色块、复杂渐变、营销海报式排版。
6. **密度可控**：信息多时拆页，不通过缩小字体解决。
7. **内容与样式分离**：产品内容放 JSON/YAML，版式由代码控制。

## 6. 数据结构

```text
六大能力
  └─ 一级模块
       └─ 功能页面
            ├─ page_type
            ├─ title / summary
            ├─ screenshot(s)
            ├─ features
            ├─ values
            └─ process / metrics / annotations
```
