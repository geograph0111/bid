# Word 企业产品手册母版规范

## 1. 定位

本母版用于 **在途商旅企业产品手册 + 技术标/商务标产品能力章节**。不是 PPT 转 Word，也不是宣传册。核心目标是：

- A4 竖版、可打印、可导出 PDF
- Word 原生可编辑
- PC / 手机截图是功能证据，而非装饰
- 100+ 页持续使用时保持稳定的视觉系统
- 同一份产品内容可以切换不同视觉风格，而不改变内容数据

## 2. 页面基准

- 纸张：A4 竖版
- 页边距：上 18 mm / 下 17 mm / 左 20 mm / 右 20 mm
- 正文宽度：约 170 mm
- 正文：Microsoft YaHei 10.2 pt
- 一级功能标题：20–21 pt
- 二级区块标题：11–13 pt
- 表格正文：8.8–9.5 pt
- 单页标题不超过两行
- 单页最多 8 个功能点，超过则拆页

## 3. 五套视觉与排版母版

五套样式共用同一套数据模型和页面组件，只改变视觉层与空间编排。命令：

```bash
python src/generate_manual.py --data data/sample_manual.json --style clean_blue
python src/generate_manual.py --data data/sample_manual.json --style teal_grid
python src/generate_manual.py --data data/sample_manual.json --style indigo_report
python src/generate_manual.py --data data/sample_manual.json --style amber_standard
python src/generate_manual.py --data data/sample_manual.json --style green_governance
python src/generate_manual.py --data data/sample_manual.json --all-styles
```

### A. clean_blue｜专业蓝白

**定位：通用技术标 / 产品手册主母版**

- 白底 + 浅蓝信息区
- 标题 → 大截图 → 功能说明表 → 应用价值
- 结构最稳定，阅读路径最直接
- 适合机票、酒店、火车、用车、审批、预算、发票、对账等大多数产品功能
- 推荐作为正式投标文件的默认风格

### B. teal_grid｜现代青绿

**定位：SaaS 产品能力 / 系统架构 / 数字化能力章节**

- 青绿色强调色
- 左侧产品截图 + 右侧核心能力摘要
- 更强调“界面 + 能力”的对应关系
- 适合系统集成、数字化平台、移动端协同、智能化能力

### C. indigo_report｜稳重靛蓝

**定位：大型企业 / 集团客户 / 数据能力章节**

- 靛蓝强调色
- 功能说明表置前，产品截图作为证据置后
- 更接近咨询报告和技术白皮书的阅读逻辑
- 适合 BI、风控、数据分析、运营管理、管理后台

### D. amber_standard｜商务金棕

**定位：商务方案 / 服务体系 / 项目实施章节**

- 金棕强调色，但控制饱和度
- 截图 + 结构化说明 + 双栏价值总结
- 适合服务保障、项目实施、运营服务、客户成功等内容
- 避免大面积金色，保证投标文件的正式感

### E. green_governance｜治理绿白

**定位：合规、风控、管理机制、企业治理能力**

- 绿色强调色 + 白色背景
- 能力卡先行，截图作为功能证据
- 适合差旅政策、预算控制、合规校验、风险预警、审计与治理

## 4. 页面组件体系

### 4.1 标准功能页 `standard`

用于绝大多数产品功能。不同视觉母版可以改变截图位置、表格顺序和价值区，但信息结构保持一致：

`功能标题 → 一句话概述 → 产品截图/能力卡 → 功能说明 → 应用价值`

### 4.2 手机端页面 `mobile_gallery`

1–3 个手机截图等宽排列，统一高度，下方使用短标签区分员工端、审批端、行程端等。

### 4.3 PC + 手机协同 `pc_mobile`

不做简单拼图，表达：

`管理端动作 → 企业管理结果`  
`员工端操作 → 移动服务结果`

### 4.4 流程 / 步骤 `process` / `steps`

采用编号步骤、短说明、关键控制点，适合申请、审批、预订、退改、对账、结算、报销等业务流程。

### 4.5 数据看板 `dashboard`

`Dashboard 截图 → 核心指标 → 指标解释 → 管理价值`。

### 4.6 能力总览 `overview`

用于章节开篇、能力地图和模块导航，不承担大段正文。

## 5. 商旅 SaaS 截图规范

### PC 截图

- 建议最大宽度 148–158 mm
- 保持原始比例，不拉伸变形
- 多区域说明使用 ①②③ 编号
- 编号与下方功能说明一一对应

### 手机截图

- 单图居中或与说明区组合
- 2 图等宽
- 3 图等宽三列
- 高度统一，不按原始像素直接排列

### 截图边框

统一使用极浅背景 + 细边框，不给截图增加重阴影，不把截图处理成营销海报。

## 6. 投标文件专用排版原则

1. **证据优先**：功能截图、流程、指标、接口关系应优先于装饰。
2. **评审友好**：评审人员可以快速定位“功能是什么、在哪里、怎么实现、带来什么价值”。
3. **一页一主题**：不要为了节省页数把多个不相关功能挤在同一页。
4. **不依赖大图承载文字**：所有核心文字必须可搜索、可复制、可编辑。
5. **不过度视觉化**：避免海报式大色块、过大插画、复杂渐变。
6. **密度可控**：宁可拆成两页，也不通过缩小字体解决信息过载。
7. **内容与样式分离**：产品内容放 JSON/YAML，Word 样式由代码统一控制。

## 7. 数据结构

```text
六大能力
  └─ 一级模块
       └─ 功能页面
            ├─ page_type
            ├─ title / summary
            ├─ screenshot(s)
            ├─ features
            ├─ values
            └─ process / metrics / annotations
```
